1. docker start -> 기본적으로 백그라운드 실행입니다. -> -d가 자동으로 붙음s
2. docker create --name ... -p ... nginx
    => 이 후에 docker start -ai mynginx
    => 터미널이 먹혀버림 -> exit로 나오면 프로세스 종료


3. 커스텀 도커 파일 키워드
3-1. From -> 기존 이미지 기반으로 새로운 이미지를 만듬
3-2. Copy -> Copy 호스트-파일 이미지-내부-경로
    => 내 호스트 파일이 컨테이너 이미지 내부 경로에 위치하게 됩니다.



4. Expose 80
4-1. 이 이미지로 만든 컨테이너는 n 포트를 사용할 것이라고 문서화하는 역할입니다. 


5. hello-world 이미지-컨테이너
5-1. hello-world 이미지에는 /hello이라는 실행 프로그램, 필요한 최소 라이브러리가 있습니다.
5-2. hello-world 컨테이너 시작 -> /hello 실행 -> 메시지 출력 -> 종료(exit) -> 컨테이너 종료
5-3. 출력 -> 종료 흐름입니다.
5-4. stdout → "Hello from Docker!" 이런것을 출력하고 종료합니다.


6. create할 떄 -it
6-1. i, 생성된 컨테이너는 표준 입력을 열어둬라 -> 키보드 입력을 받을 수 있습니다.
6-2. t, 원래 bash는 터미널 프로그램과 함께 사용하는 프로그램 -> 즉 bash != 터미널
    => 그래서 -t를 통해 가상의 터미널을 생성해서 붙여줘야 합니다.


7. start 할 떄 -ai
7-1 a, 내 터미널과 컨테이너 표준 입력을 연결하는 옵션 -> 없으면 create에서 만든 가상 가상 터미널과 내 터미널이 연결되지 않습니다.
    => a 옵션을 주면 내 터미널과 컨테이너 가상 터미널이 연결됩니다. -> 가상 터미널은 자동으로 bash와 연결됨
7-2. i, 내 키보드 입력을 컨테이너로 전달하는 옵션입니다.


8. run 할 떄 -it
8-1. i는 컨테이너의 표준 입력을 열어둡니다. -> 즉, 키보드 입력 받을 수 있습니다.
8-2. i는 동시에 현재 터미널의 입력도 연결합니다. -> 즉, 키보드 입력을 컨테이너에 전달하는 옵션도 수행
8-3. t는 컨테이너 안에 가상 터미널을 생성합니다. 
8-4. a가 없는데 run은 자동으로 현재 터미널과 가상 터미널을 연결하는 attach기능을 수행합니다.
